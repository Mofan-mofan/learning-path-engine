# 学习路径引擎 · app 说明

给一篇半导体论文，自动生成「要读懂它该学哪些知识点、按什么顺序学、去哪找资料、
还该读哪些相关文献」的学习路径。

纯静态页面，**没有构建步骤、没有后端、没有 npm 依赖**。Vue 3 和 vis-network 从
CDN 加载，数据用 `<script src>` 引入（不是 fetch），所以**双击 `index.html` 就能打开**。

---

## 一、怎么打开

**方式 A：直接双击** `index.html`。
能看图、能切论文、能打分会。但「DOI 导入」和「相关文献」两个功能会被浏览器的
`file://` 跨域策略挡住，需要方式 B。

**方式 B：起个本地服务**（要用联网功能就用这个）

```bash
cd app
python -m http.server 8123
```

然后浏览器打开 <http://127.0.0.1:8123/index.html>。

### 两层数据模型（这是整个设计的核心）

```
节点池（data/nodes-*.js）      ← 与论文无关的领域知识，人工/AI 事先写好
        +
论文库（data/papers.js）       ← 每篇论文自己的路径、判据、练习
        ↓
   一张图（运行时合成）
```

节点池里每个节点有 `scope` 字段，决定它能被哪些论文用：

- `shared`（22 个）—— 半导体物理、表征、TCAD 这类通用前置，**任何**半导体论文都能用
- `domain`（38 个）—— 只属于自己那个领域。FinFET/GAA 只进 IC 论文，
  漂移区/Baliga 优值只进功率器件论文

这就是「功率器件论文不会被塞一条『学 FinFET 才能读 Ga₂O₃』的荒谬路径」的机制。

## 三、数据怎么流的

```
输入 DOI
  ↓  literature.js: fetchPaper()
Crossref（题录、作者、ORCID、卷期页）+ OpenAlex（摘要、主题、概念、引用关系）
  ↓  pathgen.js: classifyPools()
判定这篇论文属于哪几个节点池        → papers.js 的 pools 字段
  ↓  pathgen.js: generate()
标题/主题词/摘要三处文本 → 归一化 → 逐节点打分
  ↓
核心节点 seed（得分过门槛）
  ↓ 沿 hard 依赖倒推闭包
前置节点 prereq（不懂它就看不懂 seed）
  ↓ 沿依赖边再往前一跳
延伸节点 frontier（论文没做，但紧挨着 → 喂给 L4「推进」级练习）
  ↓
主轴 spine = 基础层的 hard 链（固定、有序）
分支 branch = 全图 − 主轴
排序 ordering = 拓扑序（hard 边是可行性约束，soft 边只做偏好）
  ↓  literature.js: recommend()
五类相关文献：同作者 / 同机构同方向 / 本文引用的奠基文献 / 同主题高被引 / 引用本文的后续工作
```

### 匹配打分的三个防误命中规则

都在 `js/config.js` 的 `match` 段，配 `pathgen.js` 的 `hit()`。这三条都是实测踩过坑加的：

| 参数 | 挡住的误命中 |
|---|---|
| `shortTermLen: 3` | `ec`（想匹配临界场强 E_c）命中了 "sp**ec**ific"、"el**ec**tronic" |
| `minCollapseLen: 6` | `i v`（想匹配 I-V 曲线）压扁成 "iv" 后命中了 "gate drive"→"gatedrive" |
| 多词才做压扁匹配 | `eg`（想匹配禁带宽度 E_g）命中了 "the gate"→"th**eg**ate" |

压扁匹配本身是必要的：OpenAlex 用倒排索引存摘要，还原后下标和公式处的空格会丢，
`turn-on voltage` 会变成 `turn-onvoltage`、`Ga2O3 planar` 会变成 `Ga2O3planar`。

## 四、哪些是自动的，哪些不是（重要）

界面上会用「自动生成 / 人工策划」标签和提示条明确标出来，这里说全：

**自动**
- 题录、摘要、作者与机构、被引数（Crossref + OpenAlex）
- 领域归属判定（该用哪几个节点池）
- 节点选择、主轴/分支划分、学习顺序
- Rubric 的节点足迹、练习任务骨架
- 五类相关文献推荐 + 每条的推荐理由

**不自动**
- **节点本身的知识内容**（description / resources / 掌握标准）—— 来自 `data/nodes-*.js`，
  是人工/AI 事先写好的。引擎能决定「学哪些、按什么顺序、去哪找资料」，
  但讲解质量取决于节点池的覆盖度和质量。
- **Rubric 判据文字和练习任务的具体内容** —— 写得可判需要论文正文里的真实数字，
  而接口只给得到摘要。导入时只能生成通用模板。

想要高质量版本：点右上角**「导出给 AI 改写」**，把论文记录 + 生成结果打包成一段文字，
粘给 AI，让它按论文正文改写 rubric 和 practice_tasks，再把结果存回 `data/papers.js`。
导出文本里已经写清了「只改这两个字段，nodes/edges/path_graph 是算出来的不要动」。

`data/papers.js` 里第二篇论文（Ga₂O₃ vs SiC 中压 MOSFET）就是这么做出来的：
路径是算法生成的，rubric 和四个练习是人工撰写的，文件里用 `rubric_source: "curated"`
标了出来。

## 五、可以怎么让 AI 改

直接把下面这些话丢给 AI，每条都只会动到一两个文件。

**调参数（改 `js/config.js`）**
- 「自动生成的路径节点太多了，帮我把核心节点收紧一点」
- 「相关文献每一类只想要 3 条，不是 5 条」
- 「『同主题高被引』这一类先关掉，我看不上」
- 「『同主题』这一类推回来的东西太杂，帮我把概念具体度门槛调高」

**加知识点（改 `data/nodes-*.js`）**
- 「功率器件池里缺『雪崩倍增与电离系数』这个节点，帮我按现有格式补一个，
  依赖边接到 `sp.pn.breakdown` 上」
- 「`pw.thermal` 这个节点的学习资源太少了，帮我补三条，其中至少一条是 B 站的」
- 「新建一个『光电子器件方向』的节点池，先写 15 个节点」
  （这条要同时改 `index.html` 的脚本加载和 `config.js` 的 `pools` 数组，
   `config.js` 里已经写了三步说明）

**加论文（改 `data/papers.js`）**
- 「把 DOI 10.xxxx/xxxxx 这篇固化进论文库，路径用自动生成的结果，
  rubric 和练习你按摘要帮我起草」
- 「第二篇论文的 L2 练习要求太模糊，帮我改成能判通过/不通过的」

**改界面（改 `index.html` + `css/style.css`）**
- 「节点详情里把『学习资源』挪到『掌握标准』上面」
- 「相关文献的卡片加上期刊影响因子」
- 「图谱里核心节点的颜色太浅了，换个对比度高的」

**改推荐逻辑（改 `js/literature.js`）**
- 「加一类推荐：同一个期刊上同主题的其它文章」
- 「推荐理由里把被引数换成『同年同主题里的被引分位』」

提要求时**说清你想要的行为，不用说改哪个文件**——`config.js` 和这份 README
就是为了让 AI 能自己找对地方。

## 六、已知限制

- **视口为 0 的无头浏览器里看不到图**。vis-network 需要容器有实际宽高才能布局，
  容器宽度为 0 时图谱画不出来（数据本身是对的）。正常浏览器无此问题。
- **OpenAlex 的作者消歧不准**。所以「同作者」这一类必须配主题过滤，
  否则贾仁需名下 112 篇会混进钙钛矿、电化学传感器。
- **摘要可能拿不到**。Crossref 常没有摘要，OpenAlex 的摘要是倒排索引还原的，
  下标处空格会丢、偶尔缺一小段。拿不到摘要时界面会明确警告「自动路径质量会明显下降」。
  这种情况可以在 `data/papers.js` 里手工补 `abstract`，或用 `focus_nodes` 强制指定节点。
- **`data/resource_urls.js` 只覆盖了 IC 器件方向**。功率器件方向（`pw.` 开头）的资源
  还没登记链接，点开会走 `app.js` 里的兜底检索（B站/Wikipedia/Google Scholar/Bing），
  能跳到搜索结果页，但不是精确直达。
- **localStorage 上限约 5MB**，导入的论文和推荐缓存都存在里面，够存几百篇。
  清浏览器数据会丢，重要的论文建议固化进 `data/papers.js`。

### 实测过但明确不用的信号

记在 `js/config.js` 的 `recommend` 段注释里，别再走回头路：

- OpenAlex 的 `related_works` 字段 —— 按字面词匹配，给 Ga₂O₃ 论文推出液晶、场论的文章
- 单用 `topics.id` 过滤 —— 命中 11 万篇，被 ZnO / 二维材料淹没
- `institutions.lineage` —— 接口直接返回 400
- 单用 `author.id` 不加主题过滤 —— 作者消歧不准
- 从标题里截前 N 个实词当检索词 —— 截到的是 Static / Dynamic / Performance，
  真正有信息量的 Ga2O3 / SiC / Planar / Gate / MOSFETs 排在后面被截掉了
- 只用 `primary_topic.id` 不加器件概念 —— 它是材料体系级的（Ga₂O₃ 主题 12426 篇），
  按被引降序拿到的是紫外探测器综述，对读懂功率 MOSFET 论文没用
