# 学习路径引擎

给一篇半导体论文的 DOI，它自动生成一条学习路径：**要读懂这篇论文该先学哪些知识点、
按什么顺序学、每个知识点去哪找资料、以及还该读哪些相关文献**。

纯静态页面，**零构建、零后端、零 npm 依赖**。Vue 3 和 vis-network 从 CDN 加载，
数据用 `<script src>` 引入（不是 fetch），所以双击 `app/index.html` 就能打开。

**在线试用**：<https://mofan-mofan.github.io/learning-path-engine/app/>
（DOI 导入和相关文献两块要联网抓 Crossref / OpenAlex，本地用 `python -m http.server` 起服务更稳）

---

## 为什么做这个

读一篇器件论文真正的卡点不在"这篇写了什么"，而在**它默认你已经会了哪些东西**：
一句"利用场板缓解漂移区电场峰值"，背后是衬底、外延、器件工艺、表征四层的十几前置知识点，
而没人会告诉你缺的是哪几个、该按什么顺序补。

这个引擎做的事：把论文文本对着一张**人工写的知识点依赖图**去匹配，倒推出缺口的闭包，
再按依赖边排出可执行的顺序。图是死的，路径是每次算出来的——所以换一篇论文不用重做数据。

## 两层数据模型（整个设计的核心）

```
节点池（data/nodes-*.js）   ← 与论文无关的领域知识，人工/AI 事先写好
        +
论文库（data/papers.js）    ← 每篇论文自己的路径、判据、练习
        ↓
      一张图（运行时合成）
```

现在装了两套节点池：**IC 器件方向 35 个节点**（`ic.device`）与
**宽禁带功率器件方向 25 个节点**（`power.wbg`），共 60 个知识点、90 条依赖边。
每个节点带 `scope` 字段（`shared` 22 个 / `domain` 38 个），这就是
"功率器件论文不会被塞一条『先学 FinFET』的荒谬路径"的机制。

论文库里固化了 2 篇：一篇人工策划、一篇全自动生成，界面上用标签区分。

## 哪些是自动的，哪些不是

**自动**：题录/摘要/作者机构/被引数（Crossref + OpenAlex）、领域归属判定、
节点选择、主轴与分支划分、学习顺序（拓扑排序）、Rubric 的节点足迹与练习骨架、
五类相关文献推荐（同作者 / 同机构同方向 / 本文引用的奠基文献 / 同主题高被引 /
引用本文的后续工作），每条推荐都带机器可核验的理由。

**不自动**（这部分别指望算法）：
- **节点本身的知识内容**（讲解、学习资源、掌握标准）来自人工写的节点池，
  引擎只决定"学哪些、什么顺序、去哪找资料"；
- **Rubric 判据文字和练习任务的具体内容**——写得可判需要论文正文里的真实数字，
  而公开接口只给得到摘要，导入时只能出通用模板。

要高质量版本就点右上角**「导出给 AI 改写」**，把论文记录 + 生成结果打包成一段文本，
让 AI 按论文正文改写 `rubric` 和 `practice_tasks`，再存回 `data/papers.js`。
`data/papers.js` 里第二篇就是这么做出来的，并用 `rubric_source: "curated"` 标了出处。

## 仓库结构

| 路径 | 是什么 |
|---|---|
| `app/index.html` | 双击即用的入口 |
| `app/js/config.js` | **所有可调参数**。想调阈值、开关某类推荐、改文案，先来这里 |
| `app/js/pathgen.js` | 文本规范化 → 节点匹配打分 → 核心/前置/延伸 → 主轴分支 → 拓扑排序 |
| `app/js/literature.js` | 抓 Crossref + OpenAlex，五类相关文献推荐 |
| `app/js/autogen.js` | 编排层：DOI → 完整论文记录 |
| `app/data/nodes-*.js` | 节点池（知识点 + 依赖边），加节点改这里 |
| `app/data/papers.js` | 论文库（固化论文的路径、判据、练习） |
| `app/README.md` | **进 app 之前先读它**：文件职责表、数据流、三条防误命中规则、已知限制 |
| `01`～`05` `.md` | 五份设计文档。改数据结构之前值得先看，尤其 `04` 的粒度判据 |

设计文档：`01` 为什么做这个东西 → `02` Schema v0.1 → `03` **现行 v2.0，三个关键决策在这里**
→ `04` 知识点该切多细的判据（加节点前必读）→ `05` Schema 实填与最小闭环（`pathgen.js` 照它实现）。

## 想让 AI 帮你改

`app/README.md` 第五节列了可以直接丢给 AI 的话术。刻意保持"一个需求只动一两个文件"：
调参数只碰 `config.js`，加知识点只碰 `nodes-*.js`，改交互才碰 `app.js`。

## 已知边界

- 摘要可能拿不到（Crossref 常缺，OpenAlex 的摘要由倒排索引还原，下标处空格会丢）。
  拿不到时界面会明确警告"自动路径质量会明显下降"。
- OpenAlex 作者消歧不准，所以"同作者"那类推荐必须配主题过滤。
- `data/resource_urls.js` 只覆盖了 IC 器件方向；功率器件方向的资源链接走兜底检索，
  能到搜索结果页但不是精确直达。
- 图谱在容器宽度为 0 的无头浏览器里画不出来（vis-network 的限制，数据本身没问题）。

完整清单在 `app/README.md` 第六节，那里还记了**实测过但明确不用的六种推荐信号**
（`related_works`、`topics.id` 单用、`institutions.lineage`……）——提改进需求前先看一眼，
免得走回头路。
